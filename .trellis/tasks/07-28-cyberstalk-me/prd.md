# 赛博视奸设备状态展示网站

## Goal

做一个**公网完全公开**的网站，让任何访客（"视奸者"）能近实时看到作者本人当前在各设备上正在做什么，展示经脱敏的、不敏感的设备活动信息，营造"赛博视奸"的趣味/展示效果。

## Background / Confirmed Facts

- 全新项目（greenfield）。仓库当前仅含 Trellis 脚手架与 `.trellis/spec/` 占位规范（均为 "To fill"），无历史代码约束，技术栈自由。
- 开发环境：Windows 11。

## Key Decisions

| 维度 | 决定 |
|------|------|
| 采集方式 | **纯自建上报客户端**：每台设备跑常驻程序主动上报活动信息，追求最丰富的"视奸"信息量。 |
| 覆盖设备 | **Windows 电脑 + Android 手机/平板**（无 iOS）。 |
| 展示字段 | **当前前台应用/窗口活动、在线状态/活跃度、电量/充电/网络类型**（不含音乐）。 |
| 脱敏边界 | **应用名 + 规则映射**：默认只展示"应用名 + 友好活动描述"，隐藏原始窗口标题；可配白名单对个别应用放开更多。映射在**设备端**完成，原始标题不离开设备。 |
| 访问控制 | **完全公开**，无需登录。安全性依赖脱敏策略。 |
| 部署 | **低成本常驻 VPS**，可用 SSE 做实时推送。 |
| 技术栈 | **后端 Go**、**Windows 客户端 Go**（单二进制/单 exe，部署与分发最省心）、前端 React+Vite+TS（UI 组件优先 shadcn/ui + Tailwind，图标用 lucide-react，动效用 Framer Motion，均不自己手写）、Android Kotlin。契约用 Go struct（server/client 共享）+ 对应 TS 类型给前端。 |
| 交付顺序 | **Android 延后**：先交付「后端 + 前端 + Windows 客户端」，Android 作为后续子任务。任务拆为 parent + 子任务。 |

## Requirements

### R1 上报客户端（每类设备一个）
- R1.1 Windows 客户端：常驻采集当前前台窗口（映射为应用名+活动描述）、键鼠空闲时长、电量/充电状态、网络类型，按固定间隔上报后端。
- R1.2 Android 客户端：前台服务常驻，采集当前前台 App（映射后）、电量/充电、网络类型、活跃/在线，上报后端。
- R1.3 两端均在**设备端**完成脱敏映射（配置文件/规则：app→友好描述，白名单放开），仅上报映射后的结果，不上报原始标题。
- R1.4 每台设备用独立 token 鉴权上报。

### R2 后端
- R2.1 接收上报接口，校验设备 token，保存"每台设备的最新状态"。
- R2.2 判定设备在线/离线：超过阈值未上报即视为离线，并记录"最后活跃时间"。
- R2.3 面向前端的只读实时推送（SSE），把状态变化推给所有访客；提供一次性快照接口。
- R2.4 上报数据仅保存"最新状态"，不长期留存历史活动明细。

### R3 前端展示网站
- R3.1 完全公开页面，展示每台设备一张卡片：设备名、在线状态、当前活动描述、活跃/空闲、电量与充电、网络类型、最后活跃时间。
- R3.2 通过 SSE 近实时更新，无需刷新。
- R3.3 离线设备有明确视觉区分。

## Acceptance Criteria

> MVP 验收范围：AC1、AC3–AC6。AC2 随延后的 Android 子任务交付，不阻塞本轮验收。

- [ ] AC1：Windows 客户端启动后，网站对应卡片在 ≤ 上报间隔+阈值内显示其当前应用名与活动描述（如"VS Code · 在写代码"），且**不出现**原始窗口标题中的项目名/文档名/页面标题。
- [ ] AC2（延后 · Android 子任务）：Android 客户端启动后，网站卡片显示其当前 App（映射后）、电量与充电状态、网络类型。
- [ ] AC3：任一设备停止上报超过离线阈值后，网站在数秒内将其显示为"离线"并展示最后活跃时间。
- [ ] AC4：无痕/未登录浏览器直接打开公网 URL 即可看到全部设备卡片（无需任何认证）。
- [ ] AC5：页面在设备状态变化时自动更新，无需手动刷新（SSE 生效）。
- [ ] AC6：非法或缺失 token 的上报请求被后端拒绝。

## Out of Scope（MVP 不做）

- 历史时间线 / 过去 N 小时活动回放（仅保存与展示当前状态 + 最后活跃时间）。
- iOS 设备接入。
- 正在听的音乐、地理位置、屏幕截图缩略图等更敏感/更复杂字段。
- 访客侧登录、评论、多用户（只展示作者本人设备）。

## Risks

- **Android 客户端成本最高**：需原生 App（UsageStatsManager 取前台 App + PACKAGE_USAGE_STATS 授权 + 前台服务保活），是本项目最大工作量与不确定性来源。**已决定延后**为独立后续子任务。
- **脱敏遗漏**：完全公开下，映射规则若覆盖不全可能通过应用名/描述间接泄露。默认从严（未知应用只显示通用类别或"使用中"），白名单显式放开。
- **保活/续航**：Android 前台服务与厂商省电策略可能杀后台，影响上报连续性。
